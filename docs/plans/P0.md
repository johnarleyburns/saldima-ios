## Risks and open questions

- **XML-canonical migration landed (#6/P0-5 superseded).**
  `docs/architecture/TECHNICAL-DESIGN.md`'s Phase 1-2 is done: `BookStore`
  is now backed by `XMLBookDocument` (parse once, mutate in memory,
  atomically rewrite on save, the same way desktop GnuCash's own XML
  backend behaves); `BookWriter.create()` and `BookImporter.materialize()`
  both write XML. SQLite is import-only now (`SQLiteBookReader`), plus a
  transparent-open fallback for any file that is still SQLite-dialect on
  disk — it is rewritten as XML the first time anything saves. P0-5's
  original framing ("SQLite actor lists a fixture book's account tree") is
  historical; the real account-tree behavior it specified is preserved
  (all 63 existing tests pass unchanged against the new engine) and is now
  implemented against XML. Zero-knowledge sync (`SaldimaSync`, Phase 4+)
  stays deferred per the earlier phasing decision.
- **Xcode 27 runner.** CI assumes a macOS image with Xcode 27 / iOS 27. If it is
  absent, the compile job is blocked; do not lower the target silently.
- **Design/GTM changes.** The Design doc adds `SaldimaSync`, `api-contract`
  fixtures and a pinned `Fixtures/` directory; this plan reserves those
  directories so the layout does not move later. The Go-to-market doc adds
  "no analytics, source link in About"; the shell carries both.
- **Account-tree vector.** A synthetic vector now crosses tracks (web commit
  `5fa44eb`), so the tree builder is compared web ↔ iOS. The real-book vector
  keeps the same schema and remains blocked on the owner's fixture (#16).
- **Vector pinning.** The pin is a commit SHA, not a branch. Updating it is its
  own PR with regenerated files.
- **Purchase model — resolved.** Was open as of this P0 plan; decided and
  shipped under P1-MOBILE's M4 (`SaldimaCore/Supporter.swift`,
  `Saldima/Features/Support/SupporterStore.swift` using real StoreKit 2
  `Product`/`Transaction.updates`/`purchase()`, wired into Settings via
  `SupporterCard`): a one-time, optional **Supporter** consumable
  (`guru.parso.saldima.support.dev`) that never gates a feature. Only the
  App Store Connect product record itself remains owner-only.
- **SQLite on Linux.** The Linux container needs `libsqlite3-dev`; the CI job
  installs it before `swift test`.
