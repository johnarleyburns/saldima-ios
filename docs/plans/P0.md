## Sequencing

1. Docs and issues (this PR).
2. Scaffold + guards, then CI. Do not add feature code before `swift test` and
   the guards run on a PR.
3. Clock/ID seams before any logic that needs time or GUIDs.
4. Money/Guid, pulling the web vectors at the pinned SHA.
5. SQLite actor against a fixture.
6. Empty Liquid Glass shell, then the owner's device check.
7. Exit gate.

## Risks and open questions

- **Xcode 27 runner.** CI assumes a macOS image with Xcode 27 / iOS 27. If it is
  absent, the compile job is blocked; do not lower the target silently.
- **Design/GTM changes.** The Design doc adds `SaldimaSync`, `api-contract`
  fixtures and a pinned `Fixtures/` directory; this plan reserves those
  directories so the layout does not move later. The Go-to-market doc adds
  "no analytics, source link in About"; the shell carries both.
- **Account-tree vector.** Web P0-5 is blocked on the same human fixture, so the
  iOS account-tree cross-check cannot close until both land. Tracked on #6.
- **Vector pinning.** The pin is a commit SHA, not a branch. Updating it is its
  own PR with regenerated files.
- **Purchase model.** Optional one-time StoreKit 2 unlock versus free standalone
  remains open; not in P0.
- **SQLite on Linux.** The Linux container needs `libsqlite3-dev`; the CI job
  installs it before `swift test`.
